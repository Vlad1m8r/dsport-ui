# UI Guidelines & TMA Performance Standards

Этот документ фиксирует стандарты верстки для Telegram Mini App.

---

## 1. Glassmorphism

- Использовать класс `.glass`
- blur ≤ 16px
- Запрещены вложенные стеклянные блоки
- Обязателен fallback через @supports

---

## 2. Производительность

- Запрещено `background-attachment: fixed`
- Фон реализуется через фиксированный слой (`.ui-app-layout::before`)
- `will-change` только на реально анимируемых элементах

---

## 3. Цветовая система

- Accent всегда фиолетовой гаммы
- Используются только токены (`var(--...)`)
- Светлая и темная темы должны сохранять бренд

---

## 4. Telegram Safe Area

Используются переменные:
- `--tg-content-safe-area-inset-top`
- `--tg-content-safe-area-inset-bottom`
- `--tg-safe-area-inset-bottom`

---

## 5. Каскадность, слои и позиционирование

- При использовании фонового слоя через `::before` контент поднимается над фоном селектором:
  - `.ui-app-layout > *:not(.footer-nav)`
- Фиксированные элементы (например, `FooterNav`) должны быть исключены из общих правил, которые задают `position`.
- Запрещено неявно перетирать `position: fixed` через широкие селекторы вида `> *`.
- Для фиксированных навигационных слоёв сохранять явные параметры:
  - `position: fixed`
  - корректный `bottom` через safe area токены
  - `z-index` выше контента

---

## 6. Правила оценки рисков для AI-агента

Перед изменениями в стилях агент обязан проверить риски регрессий:

1. **Иерархия DOM и селекторы**
   - Кого реально затронет селектор (`.block *`, `.block > *`, `:not(...)`).
   - Нет ли совпадений с глобальными контейнерами/навигацией/оверлеями.

2. **CSS-каскад и специфичность**
   - Какие правила будут перезаписаны после изменения.
   - Не ломаются ли `position`, `z-index`, `pointer-events`, `overflow`, `transform`.

3. **Слои и контекст наложения**
   - Изменения `position`/`z-index`/`transform` не должны ломать fixed/sticky элементы.
   - Фоновые слои не должны перекрывать интерактивный контент.

4. **Telegram WebView риски**
   - Проверка safe area отступов.
   - Проверка поведения при скролле и изменении высоты viewport.

5. **Чек перед PR**
   - Локально проверить ключевые экраны, где есть fixed/sticky элементы.
   - Подтвердить отсутствие регрессий скролла и позиции нижней навигации.
