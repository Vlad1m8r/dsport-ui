# UI FLOWS (MVP)

## Каркас приложения (routing/providers/http client/initData)
- Routing: React Router, маршруты объявлены в `src/app/router.tsx`.
- Providers: React Query (QueryClientProvider), Telegram WebApp SDK и тема Telegram подключаются в app-layer.
- HTTP client: только `src/shared/api/http.ts`, базовый URL из `import.meta.env.VITE_API_BASE_URL`.
- InitData: читается через `src/shared/lib/telegram.ts`, заголовок `X-Tg-Init-Data` добавляется автоматически.

## Список экранов MVP
- `/templates`
- `/templates/new`
- `/templates/:id/edit`
- `/start`
- `/workouts/:id`
- `/workouts`

## Переходы между экранами
- `/templates` → `/templates/new` (создать шаблон).
- `/templates` → `/templates/:id/edit` (редактировать шаблон).
- `/templates` → `/start` (перейти к запуску тренировки).
- `/templates` → `/workouts` (перейти к истории тренировок).
- `/start` → `/workouts/:id` (после старта тренировки).
- `/start` → `/workouts` (перейти к истории тренировок).
- `/workouts/:id` → `/workouts` (завершить тренировку и вернуться в историю).
- `/workouts` → `/workouts/:id` (открыть тренировку из списка).
- Любой экран → `/templates` (через навигацию/BackButton).

## Общие состояния
- Loading: skeleton/спиннеры, блокировка действий, предотвращение повторных запросов.
- Empty: объясняющий текст + CTA (создать шаблон/начать тренировку).
- Error: человекочитаемое сообщение + retry.
- Success: краткое подтверждение (toast/inline) и актуализация списка.

## Экран: /templates
**Цель:** список шаблонов, быстрые действия (создать/удалить/перейти к редактированию).

**Ввод пользователя:**
- Нажать «Создать шаблон» (переход на `/templates/new`).
- Нажать «Удалить» у шаблона.
- Нажать «Редактировать» у шаблона.
- Нажать «К запуску тренировки».

**Основные компоненты:**
- Список карточек шаблонов.
- Кнопка «Создать шаблон».
- Ссылка/кнопка перехода на экран запуска тренировки.
- Пустое состояние.

**API endpoints:**
- `GET /api/templates` — список.
- `DELETE /api/templates/{id}` — удалить.

## Экран: /templates/new
**Цель:** создать шаблон тренировки.

**Ввод пользователя:**
- Название шаблона.
- Нажать «Создать».

**Основные компоненты:**
- Простая форма с контролируемым input `name`.
- Кнопка «Создать» (disabled, если `name` пустой/blank).
- Текст ошибки при неуспешном создании.

**API endpoints:**
- `POST /api/templates` — создать шаблон.

**Переход после успеха:**
- `navigate(/templates/:id/edit)`.

## Экран: /templates/:id/edit
**Цель:** редактирование существующего шаблона в client-only черновике (имя, упражнения и плановые подходы).

**Ввод пользователя:**
- Изменить название шаблона.
- Добавить упражнение через shared ExercisePicker.
- Удалить упражнение из шаблона.
- Добавить/удалить плановые подходы по каждому упражнению.
- Заполнить значения подходов в зависимости от типа упражнения.
- Сохранить изменения.

**Основные компоненты:**
- Поле названия шаблона с валидацией (не пустое).
- Список упражнений шаблона.
- Кнопка «Добавить упражнение» (переход в `/pickers/exercises?returnTo=/templates/:id/edit&mode=template`).
- Для каждого упражнения: карточка, кнопка удаления и список подходов.
- Для подходов:
  - `REPS_WEIGHT` → только input `plannedReps`.
  - `TIME` → только input `plannedDurationSeconds`.
- Кнопка «Сохранить» с отправкой PUT и статусами ошибки/успеха.
- Кнопка «Сбросить» для очистки черновика и возврата к данным последнего GET.

**API endpoints:**
- `GET /api/templates/{id}` — загрузить текущий шаблон.
- `GET /api/exercises` — каталог упражнений (имя + type для UI и валидации).
- `PUT /api/templates/{id}` — сохранить изменения шаблона.

**Правило сохранения:**
- Источник правды для UI на экране редактирования — локальный draft шаблона.
- Draft хранится в `sessionStorage` и сохраняется при переходе в `/pickers/exercises` и обратно.
- На backend отправляется только явное сохранение по кнопке «Сохранить» (без авто-`PUT`).

## Экран: /start
**Цель:** старт тренировки (с шаблоном или без).

**Ввод пользователя:**
- Выбор шаблона и запуск по нему.
- Запуск тренировки без шаблона.

**Основные компоненты:**
- Список шаблонов.
- Кнопки «Начать по шаблону» и «Начать без шаблона».
- Empty state с переходом к созданию шаблонов.

**API endpoints:**
- `GET /api/templates` — список шаблонов.
- `POST /api/workouts/start` — запуск тренировки.

## Экран: /workouts/:id
**Цель:** ведение текущей тренировки (упражнения/подходы, ввод reps/weight/duration).

**Ввод пользователя:**
- Добавить упражнение через общий ExercisePicker.
- Добавить/удалить подход.
- Ввести значения подхода (поля зависят от `exerciseType`).
- Завершить тренировку.

**Основные компоненты:**
- Список упражнений.
- Карточки подходов с типозависимыми инпутами (`REPS_WEIGHT`: reps+weight, `TIME`: durationSeconds).
- Подсказки last-max рядом с упражнением.
- Кнопка «Добавить упражнение» (переход в picker) и кнопки управления подходами.
- Кнопка «Закончить тренировку» и статус «Завершена» для read-only режима.

**API endpoints:**
- `GET /api/workouts/{workoutId}` — загрузить тренировку.
- `POST /api/workouts/{workoutId}/exercises` — добавить упражнение.
- `DELETE /api/workouts/{workoutId}/exercises/{workoutExerciseId}` — удалить упражнение.
- `POST /api/workouts/{workoutId}/exercises/{workoutExerciseId}/sets` — добавить подход.
- `PATCH /api/workouts/{workoutId}/sets/{setEntryId}` — обновить подход (autosave по blur/debounce).
- `DELETE /api/workouts/{workoutId}/exercises/{workoutExerciseId}/sets/{setEntryId}` — удалить подход.
- `POST /api/workouts/{workoutId}/finish` — завершить тренировку.
- `GET /api/exercises/{exerciseId}/last-max` — last-max подсказки.

**Примечание:**
- Добавление упражнения выполняется через `/pickers/exercises` с `returnTo` и возвратом `pickedExerciseId`.
- Значения подходов сохраняются автоматически при вводе (blur и debounce 600ms), при этом в PATCH отправляются только поля, релевантные `exerciseType`.
- После завершения тренировки UI переходит в read-only и возвращает пользователя в историю.
- Валидация перед завершением: подход валиден при заполненных (reps + weight) или duration; пустые поля подсвечиваются. В будущем поля будут зависеть от типа упражнения.

## Экран: /workouts
**Цель:** список тренировок пользователя и переход к деталям.

**Ввод пользователя:**
- Открыть тренировку.

**Основные компоненты:**
- Список тренировок (история/активные).
- Пустое состояние.

**API endpoints:**
- `GET /api/workouts` — список тренировок.

## Экран: /pickers/exercises
**Цель:** выбрать упражнение в едином picker и вернуть `exerciseId` на исходный экран.

**Ввод пользователя:**
- Ввести текст в поиске по названию.
- Выбрать `scope` (ALL/SYSTEM/MY).
- Выбрать группу мышц.
- Нажать на упражнение в списке.

**Основные компоненты:**
- Поле поиска с debounce 200ms.
- Два фильтра: `scope` и `muscle group`.
- Список упражнений с количеством найденных результатов.

**API endpoints:**
- `GET /api/exercises` — каталог упражнений.
- `GET /api/muscle-groups` — список групп мышц.

**Навигация/переиспользование:**
- Экран вызывается как shared picker с параметрами `returnTo` и `mode`.
- После выбора происходит переход на `returnTo` с query param `pickedExerciseId`.
- Picker используется в потоках TemplateEditor и WorkoutPage.
